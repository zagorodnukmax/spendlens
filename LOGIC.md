# SpendLens — как устроена логика

## 1. Задача

Пользователь загружает CSV-выписку из банка. Приложение:

1. раскладывает каждую транзакцию по категориям — с помощью **Claude** (LLM от Anthropic), а если AI выключен
   или упал — по правилам (MCC-коды + ключевые слова);
2. считает статистику: доход, расход, баланс, траты по категориям и месяцам;
3. находит **подписки** (регулярные списания) и их стоимость за год;
4. находит **необычные траты** (в разы больше обычного для категории);
5. отвечает на вопросы о тратах обычным языком («Сколько я потратил на такси в октябре?»).

Это продолжение проекта Spendwise: там категория подбиралась только по ключевым словам. Здесь основную работу
делает LLM, а ключевые слова стали запасным вариантом.

| Что | Адрес | Логин / пароль |
|---|---|---|

## 2. Поток обработки выписки

```
POST /api/statements (CSV)
  │
  ├─ StatementParser: определяет формат, разбирает строки ─── ошибка → 400 "Line 7: invalid amount"
  ├─ сохраняет Statement (status = PROCESSING) и транзакции
  ├─ публикует событие StatementUploaded
  └─ сразу отвечает 201 — пользователь не ждёт AI
        │
        ▼  после коммита БД, в отдельном потоке (@Async + @TransactionalEventListener)
  StatementProcessor
  ├─ CategorizationService.categorize(все транзакции)
  ├─ записывает категорию и источник (AI / RULES) в каждую транзакцию
  └─ status = DONE (или FAILED с текстом ошибки)
        │
        ▼
  Фронт каждую секунду опрашивает GET /api/statements/{id}; увидев DONE —
  загружает insights и transactions и прекращает опрос.
```

**Почему асинхронно:** запрос к LLM на 500 транзакций идёт несколько секунд. Держать HTTP-запрос открытым
всё это время плохо: таймауты, пользователь не видит прогресса. Поэтому загрузка возвращается сразу,
а результат приходит позже.

**Почему `@TransactionalEventListener`:** обработка должна начаться только **после** коммита. Иначе фоновый
поток может прочитать выписку, которой ещё нет в БД.

## 3. Разбор CSV (`StatementParser`)

| Формат | Как определяется | Колонки |
|---|---|---|
| **MONOBANK** | первая колонка начинается с «Дата», есть колонка «MCC» | дата `dd.MM.yyyy HH:mm:ss`, детали, MCC, «Сума в валюті картки (UAH)» |
| **GENERIC** | есть колонки `date`, `description`, `amount` | плюс необязательная `mcc` |

- Разделитель (`,` или `;`) определяется по заголовку.
- Поддерживаются кавычки и `""` внутри значения (`"Bolt ride, ""airport"""`).
- Десятичная запятая (`-85,50`), BOM в начале файла, неразрывные пробелы в суммах.
- Ошибка в строке → 400 с номером строки, чтобы пользователь мог её найти.
- Ограничения: файл до 5 МБ, до 5000 строк, сумма не может быть нулём.

Знак суммы: **минус = расход, плюс = доход** (как в выписке monobank).

## 4. Категоризация

### Список категорий — фиксированный (`enum Category`)

Groceries, Cafe & Restaurants, Transport, Subscriptions, Shopping, Health, Utilities & Telecom,
Entertainment, Travel, Transfers, Cash, Income, Other.

Закрытый список нужен по двум причинам: ответ модели можно **жёстко проверить по JSON-схеме**, а статистика
сравнима между выписками.

### `CategorizationService` — кто решает

```
для каждой пачки из 40 транзакций:
    если Claude настроен:
        попробовать Claude
        ошибка (сеть, лимит, отказ модели) → вся пачка уходит в правила
    каждая транзакция, которую модель пропустила → правила
```

Итог **всегда полный**. У каждой транзакции записано, кто её категоризировал: `AI`, `RULES` или `MANUAL`
(если пользователь исправил категорию вручную). В интерфейсе это значки ✨ AI / ⚙ rules / ✎ you.

### Claude (`AnthropicClaudeGateway`)

- Официальный **Anthropic Java SDK**, модель `claude-opus-5-5`.
- **Structured output**: SDK строит JSON-схему из Java-записи `CategorizedBatch(List<CategorizedItem(index, category)>)`.
  Модель обязана ответить строго по схеме, категория — только из enum. Парсить текст вручную не нужно.
- Каждая транзакция передаётся строкой `index | MCC | сумма | описание`. По `index` ответ связывается со строкой,
  даже если модель изменит порядок или что-то пропустит.
- **Effort `low`**: классификация — простая задача, низкий effort делает её быстрее и дешевле.
- В системном промпте прямо сказано, что описания транзакций — это **данные, а не инструкции**. Это защита
  от prompt injection: в выписке может оказаться строка вроде «ignore previous instructions».
- **Refusal fallback**: если модель откажется отвечать, API сам повторит запрос на запасной модели.
  Если отказ всё же дошёл до нас, это ошибка → пачка уходит в правила.

### Правила (`RuleBasedCategorizer`)

1. Сумма > 0 → **Income**.
2. **Ключевые слова** в описании (`silpo`, `сільпо`, `bolt`, `netflix`, `аптека`, …) — совпадение ищется
   **только с начала слова**.
3. **MCC-код** (стандарт ISO 18245): `5411` → Groceries, `4121` → Transport, `6011` → Cash,
   `3000–3999` → Travel (авиалинии, отели), `5200–5999` → Shopping (розница) и т. д.
4. Иначе → **Other**.

> **Баг, найденный тестом.** Сначала ключевые слова искались как подстрока. «Банкомат Приват**Б**анк»
> содержит «атб», поэтому снятие наличных попало в «Продукты (АТБ)». Исправлено поиском с начала слова,
> на этот случай добавлен регрессионный тест.

## 5. Аналитика (`InsightsService`) — без AI

Все числа считаются обычным детерминированным кодом: суммы должны быть точными и воспроизводимыми.
LLM здесь не используется.

| Что | Как считается |
|---|---|
| Доход / расход / баланс | сумма положительных / модулей отрицательных / разница |
| По категориям | сумма, количество, доля от всех расходов; сортировка по убыванию |
| По месяцам | доход и расход по `YearMonth` |
| Топ-5 мест | группировка по «ключу продавца»: нижний регистр, без цифр и знаков (`WOG 1234` и `WOG 5678` — одно место) |

### Подписки

Транзакции группируются по ключу продавца. Группа считается подпиской, если:

- это **известный сервис** (категория Subscriptions) и списаний **≥ 2**; **или**
- у обычного продавца **≥ 3** списаний, суммы в пределах **±5 %** от медианы, интервал между ними
  **25–35 дней**.

Годовая стоимость = типичная (медианная) сумма × 12.

> Сначала порог был «2 списания и ±10 %». На демо-выписке подписками оказались **две заправки WOG**
> и **две поездки Bolt** с разницей в месяц. Порог подняли до трёх списаний и ±5 %, тест на этот случай добавлен.

### Необычные траты

В категории, где **≥ 4** расходов, трата считается необычной, если она:

- **≥ 3×** медианы этой категории **и**
- **≥ 500 грн** (чтобы кофе за 120 грн рядом с кофе за 25 грн не считался аномалией).

Переводы (Transfers) не проверяются: суммы переводов людям по природе разные.
Пример из демо: «Сільпо 4 870 грн — 8.1× your typical Groceries expense (600 UAH)».

Медиана, а не среднее: одна огромная покупка не должна сдвигать «обычный» уровень.

## 6. Вопросы к AI (`POST /api/statements/{id}/ask`)

1. Если ключ не настроен → **503** с понятным текстом, как включить AI.
2. Если выписка ещё обрабатывается → **409**.
3. Строится контекст: период, **уже посчитанные** итоги и суммы по категориям, затем все транзакции строками
   `дата | категория | сумма | описание`.
4. Запрос к Claude с effort `medium`. Системный промпт требует: отвечать на языке вопроса, коротко, с цифрами,
   перепроверять суммы, не выдумывать, если данных нет.

Готовые итоги передаются в контекст, чтобы модели не нужно было складывать сотни чисел самой: она опирается
на точные значения, посчитанные кодом.

## 7. Авторизация и изоляция данных

Так же, как в Spendwise: stateless **JWT Bearer** (HS256) через Spring Security OAuth2 Resource Server.
Id пользователя берётся из claim `sub` токена. Все запросы к выпискам идут через
`findByIdAndOwnerId(id, userIdИзТокена)`: чужая выписка возвращает **404**, а не 403, чтобы даже не раскрывать,
что она существует.

## 8. Хранилище

- По умолчанию **H2** в файле `backend/data/` — ничего не нужно ставить.
- Профиль **`postgres`** + `docker-compose.yml` — та же схема на PostgreSQL.
- Схема создаётся Hibernate (`ddl-auto: update`). Для продакшена следующим шагом стоит перейти на Flyway-миграции.

## 9. Тесты

Три уровня:

| Уровень | Команда | Что это |
|---|---|---|
| **Unit** | `./mvnw test` | один класс без Spring и БД; Claude заменён фейком или локальной HTTP-заглушкой |
| **API** | `./mvnw test` | весь Spring-контекст + H2 в памяти, запросы через MockMvc |
| **Интеграционные** | `./mvnw verify` | приложение **запускается целиком на случайном порту**, тест ходит в него по настоящему HTTP — как браузер |

`./mvnw verify` = unit + API (Surefire) + интеграционные (Failsafe, классы `*IT`). Фронт: `npx ng test --watch=false`.
В IntelliJ: вкладка **Maven → Lifecycle → verify** или правый клик по `src/test/java` → *Run 'All Tests'*.
